Версия интерфейса 0.12.0 (15)

Восстановленный существующий сайт из NFS_Dua_Ready_Website.zip.
Его исходный data/content.json сохранён побайтно. Это самостоятельный
снимок каталога: 43 дуа/азкара, 99 имён, 75 учебных материалов и 27 событий.
Он не заявлен как полная копия всех новых возможностей Flutter-приложения.
Раздел «История халифов» получает общий с приложением канонический JSON.

Локальная проверка исходников этого репозитория:
  python3 -m http.server 8765 --bind 127.0.0.1
  http://127.0.0.1:8765/
На Windows с установленным Python можно использовать:
  py -m http.server 8765 --bind 127.0.0.1
Файл index.html не рекомендуется открывать через file://: загрузка JSON
и сервис-воркер зависят от корректного HTTP(S)-размещения.

ВНИМАНИЕ: в текущем репозитории отсутствует tool/prepare_website.py,
ранее упоминавшийся в инструкции. Исходный sw.js намеренно содержит
RELEASE = null: это НЕ собранный офлайн-релиз. Интерфейс исходной версии
теперь честно сообщает «Онлайн-версия» и не пытается установить незавершённый
сервис-воркер. Не заявляйте поддержку PWA/офлайна для этой папки.

Полноценный офлайн-релиз требует отдельного проверенного упаковщика,
который заполняет RELEASE хешами всех необходимых ресурсов, проверяет их
перед установкой и включает все страницы, шрифты и JSON. Сборка и публикация
такого релиза в этом репозитории пока не подтверждены. Заполнять RELEASE
произвольными значениями или раздавать неполную офлайн-копию нельзя.

Проверки, которые можно запустить локально:
  node tests/site-wide-integrity.cjs
  node tests/navigation-smoke.cjs
  node tests/content-audit.cjs
  node --check tests/live-site-audit.cjs
Базовое измерение производительности в CI:
  node tests/site-performance-baseline.cjs
  (для последней команды нужны запущенный HTTP-сервер и Playwright;
   измерения локальны и НЕ равны скорости публичного сайта).

Подтверждённый публичный адрес:
  https://talab-al-haqq.rnafasbek.workers.dev/
22.11.2026 через GitHub Actions подтверждены HTTP 200 для 10 основных
адресов, а файлы app.js, style.css, data/content.json совпали с main по
SHA-256. Это выборка реального развертывания, не обещание работы всех функций.
Workflow «Check published site» теперь проводит HTTP-проверку и отдельный
Chromium-тест по этому адресу, сохраняет live-site-report.json и
live-browser-report.json. Вручную проверку можно запустить с другим
подтверждённым HTTPS URL через параметр site_url.
**Пока не подтверждена полноценная офлайн-сборка**: sw.js остаётся с
RELEASE = null.

Браузерные тесты выполняются в GitHub Actions, включая Chromium на
мобильных и компьютерных размерах экрана. Это не заменяет тестов на
реальных iOS/Android и проверки опубликованного хостинга.

При обновлении сохраняются ключи nfs_favs, nfs_counts, nfs_theme и прежние
идентификаторы материалов. Место чтения хранится дополнительно в nfs_reading.
Офлайн-копия готова только после статуса «Доступно офлайн».
На iPhone сначала добавьте сайт на главный экран, откройте новую иконку
онлайн и дождитесь готовности. Safari и установленное приложение могут
использовать разные хранилища. Очистка данных браузера удаляет сохранения.
