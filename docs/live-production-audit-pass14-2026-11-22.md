### Найдены риски в опубликованном ответе
1. **Не было HSTS** на домашней странице.
2. **Не было Content-Security-Policy**.
3. **Не было `X-Content-Type-Options: nosniff`**.
4. **Не было `Referrer-Policy`**.
5. **`sw.js` содержал `RELEASE = null`.** Поэтому полноценную офлайн-установку не объявляем работающей, несмотря на HTTP 200 самого файла.

Это наблюдения конкретного ответа на момент проверки; **не** доказательство наличия уязвимостей в эксплуатации. Полноценного пентеста и независимого аудита доступа не было.

## Исправления, подготовленные в PR #44
- Создан файл `_headers` по [официальным правилам Cloudflare Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/headers/): `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, минимальный `Content-Security-Policy` (`base-uri`, `object-src`, `frame-ancestors`), `Strict-Transport-Security` и `Permissions-Policy`. Это осторожное усиление без `script-src`/`style-src`, способных сломать существующие встроенные учебные скрипты. **До проверки после публикации нельзя считать эти заголовки применёнными.**
- Сетевой аудит теперь распознаёт отсутствие обязательных заголовков как ошибку **после** появления `_headers` в исходниках. При первоначальном PR старый live Worker может временно показывать старые заголовки, поэтому PR-проверка сохраняет отчёт, но не блокирует объединение из-за временного расхождения. Проверка `push` в `main` выполняется строго с несколькими попытками ожидания асинхронного развёртывания Cloudflare.
- Добавлен `tests/live-site-browser-smoke.cjs`: два размера Chromium (390 и 1280 px), все 22 опубликованные HTML-страницы, проверка HTTP, видимого заголовка, ошибок JS и горизонтальной прокрутки, плюс поиск, карточка читателя, смена темы и раздел статуса источников.
- Отчёты `live-site-report.json`, `live-browser-report.json`, `live-home-*.png` прикладываются к GitHub Actions. Исправлена логика флага `exactSourceAssetsMatch`: ошибка загрузки теперь никогда не считается успешной сверкой SHA.
- В `README.txt` зафиксирован реальный адрес с честными границами подтверждения.

**Ограничение Cloudflare:** файл `_headers` применяется к ответам, которые обслуживаются **статическими ресурсами Workers**. Если запрос обрабатывает исполняемый Worker, придётся добавлять заголовки в `Response` Worker script; на данный момент конфигурация Workers не находится в репозитории. Это будет видно после повторной публичной проверки.
