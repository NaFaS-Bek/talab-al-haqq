# Временный закрытый режим проверки

Подготовлен отдельный конфиг Wrangler, чтобы не менять действующий способ публикации до проверки владельцем. **Само создание PR не закрывает сайт.** Режим защищает все сетевые запросы к учебным материалам (HTML, JSON, JS, аудио и т. д.). Единственное открытое исключение — /sw.js, который не содержит материалов и пытается удалить старый офлайн-кеш приложения. Уже сохранённые на устройствах копии и публичные исходники GitHub отозвать нельзя. Для конфиденциальности исходников владелец должен отдельно сделать репозиторий приватным; проверить старые deployment/preview URL, forks и другие хостинги.

## Активация владельцем
1. Проверить текущий Worker и конфигурацию Cloudflare, резервную версию и привязки. Внести этот PR в main только после проверки. Не создавать новый публичный Worker.
2. На доверенном компьютере из корня актуальной копии репозитория выполнить `npx wrangler login` и `node --test tests/private-review-access.test.mjs`.
3. В Cloudflare Workers & Pages → talab-al-haqq → Settings → Variables and Secrets создать секрет REVIEW_PASSWORD (тип Secret, новый случайный пароль не короче 16 символов). Не использовать пароль из переписки; не добавлять его в git, URL, build vars или логи. Альтернатива CLI: `npx wrangler secret put REVIEW_PASSWORD --config wrangler.review.jsonc` с вводом в защищённом приглашении. Если секрет на текущем static-only Worker не поддерживается, сначала опубликовать проверенный конфиг: отсутствие секрета приводит к 503, а не открытому доступу.
4. Выполнить `npx wrangler deploy --config wrangler.review.jsonc` (предварительно проверить текущие настройки и что имя соответствует существующему Worker). Для закрытого режима отключить старую автоматическую публикацию static-only, иначе она может снять защиту. Проверить, что отключены version/preview URLs, альтернативные публичные домены; не оставлять прежние версии доступными.
5. В приватном окне без старого PWA проверить 401 для /, /stories.html, /stories-tg.html, /data/content.json и /app.js, затем проверить вход с логином review и секретом. /sw.js должен вернуть только очистку кеша. Проверить неверный пароль, отдельные языковые страницы, отсутствие кеширования. Если что-то не работает, не считать сайт закрытым. У ранее посещавших сайт возможны сохранённые копии; очистка данных сайта вручную обязательна для проверки их устройства.

HTTP Basic Auth по HTTPS: общий пароль не идентифицирует отдельных экспертов, отзыв доступа требует смены секрета. Для длительной проверки лучше Cloudflare Access с разрешёнными email и ограничением попыток входа. Перед публикацией согласовать возврат офлайн-режима и проверку источников. Старый открытый деплой не использовать как откат без согласия владельца.
