# Проверяемая офлайн-версия «Талаб аль-Хакк» — проход 15
Дата: 2026-11-23. **Область:** статический сайт в `NaFaS-Bek/talab-al-haqq` и опубликованный Workers URL `https://talab-al-haqq.rnafasbek.workers.dev/`.

## Архитектура и принципы сохранения содержания
- `tool/prepare_website.py` (Python 3, только стандартная библиотека) собирает **все 22 HTML-страницы**, `app.js`, два CSS, `data/content.json` и `data/caliph_history.json`, `manifest.webmanifest`, `icon.svg`, все файлы `fonts/` и `icons/`, `TANZIL-LICENSE.txt`. В папку сборки дополнительно переносится `_headers`. Ресурсы со стороны внешних источников, например Sunnah.com и Quran.com, **не** скачиваются и в офлайн-пакет не добавляются.
- Для каждого файла вычисляется SHA-256 **самого содержимого байтов**. `RELEASE.version` вычисляется как SHA-256 отсортированного компактного JSON, содержащего карту `resources`. Версия не зависит от времени сборки, случайного числа или даты.
- `sw.js` не включён в собственную карту хешей (иначе получилось бы рекурсивное требование к хешу себя самого). Он содержит проверяемую карту `RELEASE.resources`; любой новый выпуск требует перегенерации и коммита этого файла.
- Файл `sw.js` служит одновременно исходником механизма кеширования и подготовленной публикацией. Команда `--write-root` изменяет **только одну декларацию `const RELEASE`**, не переписывая остальные ветки поведения.
- Сборка `build/website` создаётся из байтов исходников, проверяет совпадение копий с манифестом, содержит `_headers`. Каталоги `build/`, `node_modules/` не добавляются в git.
- Тексты Корана, дуа, транскрипции, атрибуция и карточки исходного `data/content.json` не менялись и не редактировались ради PWA.

## Состояния и защита от неполного обновления
1. Первый онлайн-визит загружает неизменённые страницы, затем регистрирует подготовленный `sw.js`; сервис-воркер последовательно получает каждый ресурс и проверяет SHA-256.
2. На успешной установке все проверенные `Response` переносится в версионированный кеш; отметка `__nfs_pwa_ready__` пишется **последней**.
3. При сетевой ошибке, изменении одного файла, нехватке памяти или другом исключении новый кеш очищается, завершающая отметка **не** появляется. Версия не считается готовой.
4. Статус «Доступно офлайн» возникает по запросу `NFS_PWA_STATUS` только после успешной установки полного набора, а не по факту HTTP 200 для `sw.js`.
5. При отсутствии сети приложение не пытается принудительно регистрировать/перекачивать `sw.js`, а получает статус из уже управляющего сервис-воркера.
6. Переход на новую версию происходит после подтверждения пользователя в баннере «Доступно обновление», без очистки `localStorage` и без изменения ключей `nfs_favs`, `nfs_counts`, `nfs_theme`, `nfs_reading`. Привязка текущих клиентов к старым кешам сохраняется согласно текущему механизму SW.
7. Встроенное ограничение: внешние сайты с первоисточниками не кешируются; они требуют подключения к интернету. Сайт не должен утверждать, будто все источники доступны офлайн.

## Воспроизводимые команды

```bash
python3 tool/prepare_website.py --print-manifest
python3 tool/prepare_website.py --write-root
python3 tool/prepare_website.py --check-root
python3 tool/prepare_website.py --build build/website
python3 -m http.server 8766 --bind 127.0.0.1 --directory build/website
```

## Тесты (что именно доказывают)
- `--check-root`: наличие **точного** манифеста в закоммиченном `sw.js`, отказ при устаревшем манифесте и при добавлении/изменении любого учитываемого ресурса.
- `--build`: копирование в `build/website` и повторное сравнение SHA-256 для каждого файла; отсутствие инструментария `tool/` в папке публикации.
- `tests/offline-pwa-smoke.cjs` (Chromium, `http://127.0.0.1:8766/`): настоящее подключение `serviceWorkers:'allow'`, ожидание `Доступно офлайн`, 22 последовательные офлайн-навигации по HTML, чтение JSON каталога, сохранение избранного, счётчика, темы и истории до/после отключения сети.
- Тот же тест имитирует обновление версии `RELEASE` на локальном тестовом сервере, принимает предложение «Обновить», проверяет последующий офлайн-доступ к **новому** содержимому при сохранении `localStorage`.
- Отдельный тест с намеренно повреждённым `style.css` и заведомо несовпадающим SHA-256: установка не должна завершиться успешным состоянием `ready`; кеш неподтверждённой версии не должен сохраняться как готовый.
- `tests/site-wide-browser-smoke.cjs` продолжает проверять обычный интерфейс с блокировкой воркеров — чтобы тесты дизайна и навигации не имели побочных эффектов из-за установки SW.
- После коммита в `main`: `tests/live-site-audit.cjs` требует совпадения `sw.js` с `main`. `tests/live-site-offline-smoke.cjs` проверяет опубликованный Workers URL в браузере Chromium, полноценную установку, все 22 страницы без сети, каталог и сохранения.

## Что нельзя автоматически утверждать
- **До зелёного результата CI и проверки опубликованного адреса** нельзя писать, что PWA уже готов для посетителей.
- Chromium на GitHub runner не заменяет фактическую установку iOS Safari/Android Chrome и проверку ограничений хранения на разных устройствах, недостатка памяти, повреждённого старого кеша или обновления при прерывистом интернете.
- Работа в офлайн-режиме не подтверждает достоверность религиозных текстов — внешняя независимая богословская экспертиза остаётся открытым этапом.
- Будущее **аудиочтение** должно проектироваться отдельно, с проверкой арабского произношения и лицензий озвучивания, не добавляя в текущий PWA непроверенные аудиофайлы.
